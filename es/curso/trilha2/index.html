🧰 Requisitos previos y cuentas

El mise en place: qué instalar, las cuentas (Supabase, Telegram, OpenAI/Gemini, WHOOP) y el ~/.env con todas las claves en su lugar antes de programar.

Progreso0 de 7 · 0%
Qué es: Las herramientas básicas en la máquina: Python 3, git y la CLI del agente (Claude Code).
Por qué aprender: Sin el entorno listo, no se ejecuta ningún comando de los siguientes pasos.
Conceptos clave: Python 3 · git · venv.
Qué es: Crea un proyecto gratis en Supabase, que ofrece PostgreSQL + almacenamiento listos para usar.
Por qué aprender: Es la base de datos donde estarán todos tus datos de salud.
Conceptos clave: Proyecto · URL · service-role key.
Qué es: Hablar con @BotFather para crear el bot y recibir el token de acceso.
Por qué aprender: Telegram es la interfaz del coach; sin token, no hay bot.
Conceptos clave: BotFather · token · chat_id.
Qué es: Las API keys del modelo de lenguaje y del generador de embeddings.
Por qué aprender: Es el «cerebro» y la memoria semántica del agente.
Conceptos clave: API key · embeddings · cuota.
Qué es: Crea una app en el developer portal de WHOOP para obtener un client id y un secret.
Por qué aprender: Es lo que permite obtener datos de recuperación y HRV automáticamente (es opcional).
Conceptos clave: Client id · secret · OAuth.
Qué es: Un único archivo, fuera del repo, que reúne todos los secretos.
Por qué aprender: Centraliza las claves y las mantiene lejos de git.
Conceptos clave: ~/.env · gitignore · secretos.
Qué es: La lista que confirma que cada cuenta y cada clave ya existe.
Por qué aprender: Obtén lo que falta ahora, antes de que te quedes atascado a mitad del paso.
Conceptos clave: Cuentas · claves · entorno.

🗄️ La base de datos (Supabase)

Las 14 tablas, el pgvector para la memoria, el bucket de storage y el RLS que bloquea todo. Ejecutas las migrations y verificas la conexión.

Progreso0 de 7 · 0%
Qué es: Aplicar los archivos SQL que crean todas las tablas de una vez.
Por qué aprender: Es cómo la base de datos pasa de cero al esquema completo.
Conceptos clave: SQL · migration · idempotente.
Qué es: Las 14 tablas que guardan los datos del wearable, la sangre, el ADN, la dieta y la memoria.
Por qué aprender: Saber dónde se encuentra cada dato ayuda a consultarlo y depurarlo.
Conceptos clave: Esquema · relaciones · claves.
Qué es: La extensión de Postgres que almacena embeddings y busca por similitud.
Por qué aprender: Es lo que le da memoria semántica al coach.
Conceptos clave: Extensión · vector · similitud.
Qué es: El bucket donde se guardan fotos de comida y PDF de exámenes.
Por qué aprender: El agente necesita un lugar para los archivos sin procesar.
Conceptos clave: Bucket · carga · URL firmada.
Qué es: Reglas que bloquean cada fila para que solo su dueño pueda leerla.
Por qué aprender: Los datos de salud son sensibles; RLS es el cerrojo predeterminado.
Conceptos clave: Política · propietario · privado.
Qué es: Ejecuta un ping a la base de datos para confirmar que todo se conecta de punta a punta.
Por qué aprender: Confirma las credenciales y la red antes de seguir construyendo.
Conceptos clave: Conexión · service-role · ping.
Qué es: Insertar algunos datos de ejemplo y tu perfil inicial.
Por qué aprender: Le da al coach algo para leer desde el primer día, con cuidado de la privacidad.
Conceptos clave: Seed · perfil · cuidado.

⌚ Wearable y programación

WHOOP de punta a punta: OAuth, la autorización única, el whoop-sync.py, los dos problemas clásicos y cómo programar la sincronización y el registro de la mañana.

Progreso0 de 7 · 0%
Qué es: El flujo que intercambia tu inicio de sesión por un token de acceso a WHOOP.
Por qué aprender: Es la puerta de entrada para obtener tus datos de recuperación.
Conceptos clave: OAuth · token · refresh.
Qué es: El paso manual que haces una sola vez en el navegador.
Por qué aprender: Después de eso, la sincronización empieza a ejecutarse sola.
Conceptos clave: Consent · callback · code.
Qué es: El script que descarga el recovery, el sueño y la HRV en la base de datos.
Por qué aprender: Es lo que llena la base de datos con los datos del día.
Conceptos clave: Sincronización · upsert · API.
Qué es: Los dos tropiezos comunes: token vencido y zona horaria cambiada.
Por qué aprender: Conocerlos de antemano evita horas de depuración.
Conceptos clave: Refresh · UTC · timezone.
Qué es: Un cron que ejecuta whoop-sync.py todos los días bien temprano.
Por qué aprender: Garantiza datos actualizados antes del check-in de la mañana.
Conceptos clave: Cron · programación · registro.
Qué es: El job que envía el mensaje de buenos días del coach con tu recovery.
Por qué aprender: Es el disparador del ciclo diario de recuperación.
Conceptos clave: Cron · check-in · notificación push.
Qué es: Cómo adaptar el mismo patrón de sync para Oura, Garmin o Apple Health.
Por qué aprender: El blueprint no depende de WHOOP.
Conceptos clave: Adaptar · API · upsert.
